# Working in this repo

An NHL offseason tracker. All 32 clubs are selectable; Anaheim carries the full
editorial treatment. Static React + Vite, built to S3 and served by CloudFront.

**This repository is public.** Never commit AWS account numbers, bucket names,
distribution IDs or ARNs. They belong in `.env.deploy` (gitignored) and GitHub
Actions variables. `docs/INFRASTRUCTURE.md` describes the shape without them.

## The rule everything else serves

Facts need primary sources; anything else must be labelled as what it is.

- A **fact** traces to NHL.com, the NHL API, PuckPedia or Hockey-Reference.
- Anything not yet official — a projected lineup, an expected role — must read
  as a projection.
- A **rumour** is not a fact and never edits the roster, cap or contract data.
  It goes in the `rumors` array with a provenance chip. See `CONTRIBUTING.md`.
- Do not generate editorial content from statistics. A club without a written
  research brief gets the data-only page, which says so plainly. That is the
  correct outcome, not a gap to paper over.

No NHL, NHLI or club logos, wordmarks, crests or league photography — anywhere,
including data files. Club identity is colour and the three-letter code. Player
photos come only from Wikimedia Commons under a free licence; everyone else
gets an initials avatar. Naming a team in text is nominative use and is fine.

## Where things live

| Path | What it is |
|---|---|
| `src/data/editorial/<ABBR>.js` | One club's editorial content: hero, roster notes, ledger, camp watch, unresolved, rumors. Most content edits. |
| `src/data/editorial/index.js` | Which clubs have a brief. Adding a club here is what promotes it. |
| `src/data/status.js` | Shared status/provenance vocabulary, identical for every club. |
| `src/data/cap.js`, `contracts.json`, `points.json` | Anaheim cap, contract terms, point totals. |
| `src/data/teams.json` | The 32-club registry. Generated by `npm run league`. |
| `src/data/league/<ABBR>.json` | Per-club roster and stats. Generated; code-split so one club costs ~6KB. **This is the current roster with 2025–26 club stats attached where they exist — not a list of who played here.** |
| `src/data/coaches/<ABBR>.json` | Head coach for 2026–27 and 2025–26. Generated by `npm run coaches`. |
| `src/data/updates.json` | Drives the self-expiring NEW badge. Written by the update pass. |
| `src/lib/team.js` | Team selection: URL → cookie → per-host default. |
| `docs/INFRASTRUCTURE.md` | Hosting, DNS, deploy, IAM, runbooks. |

## Two depths of club page

The `EDITORIAL` map in `src/data/editorial/index.js` decides. A club listed
there renders the full tracker from its own module; every other club renders
roster and scoring from the NHL API with a notice explaining the narrative is
missing. Promoting a club means writing its sourced brief and module first,
then adding it to that map — the registry sits next to the modules so the two
cannot drift apart.

Components never import a club's data directly. They read the club being
rendered from `useEditorial()`; `App` loads the module on demand and provides
it. Anything genuinely shared (status labels, provenance chips) lives in
`src/data/status.js` instead.

A club's module owns everything club-specific, and **sections it omits simply
do not render**, which is always better than showing another club's numbers:

- no `cap` → no Salary Cap tab (this bug was live for one commit: CapView
  imported Anaheim's `cap.js`, so every club would have shown Anaheim's table).
  All 32 now have one; refresh a club with `scripts/parse-puckpedia.mjs`
- empty `draftClass` → no draft tab, rather than an empty panel implying the
  club made no picks (all 32 now have one, generated by `npm run draft`)
- empty `rumors` → no Rumor mill section
- no `points` / `contracts` → cards omit those lines

Derive statistics, don't retype them. A club module builds its `points` map
with `pointsFromLeague()` from `src/data/league/<ABBR>.json`, which the NHL API
already populates, so there is one source of truth rather than two copies to
drift apart.

`npm run check:editorial` (part of `npm run lint`) checks shape, not facts: that
every registered club exports what the components read, that `status:` values
match `status.js`, that a registered club has a module and vice versa, and — the
one that matters most — that no club imports another club's league file, which
would silently attribute one team's statistics to another.

**Coverage: all 32 clubs**, each with a roster comparison, ledger, draft class,
cap tab, camp watch and unresolved list. Anaheim additionally has a contracts
map, which only adds contract-expiry labels to its cap rows.

The draft table separates fact from analysis: **Drafted from** comes from the
API for every club, while **Outlook** is written and stays blank rather than
being generated. Deepening a club means reading PuckPedia for it in the
browser and adding `cap`/`contracts` to its module.

Because every club now has a brief, `TeamPage.jsx` — the data-only fallback —
renders for nobody. It is kept deliberately: it is what a club falls back to if
its module is removed or fails to load, and it is the honest default for any
future expansion club. Those written from a team reset alone carry no cap tab,
no photo credits and no draft class, and say so in their `unresolved` list,
because PuckPedia has not been read for them.

**Scope of the ledger is the offseason.** An in-season trade does not belong in
`departures`/`arrivals` even when it explains the roster. Where one materially
changes how a lineup reads — Quinn Hughes going Vancouver→Minnesota in December
— it goes in `biggestChanges` labelled as outside the window, with a scope note
at the top of the module.

**When sources disagree, say so.** Two NHL.com pages describe Roslovic's and
Sissons' moves to Toronto differently (trade vs. free-agent signing). The
module states that they joined, names the disagreement in a sourcing note, and
lists it as unresolved — rather than silently picking whichever reads better.

## Commands

```sh
npm run dev        # local
npm run build      # production build
npm run lint       # oxlint + editorial structure check
npm run league     # refresh all 32 clubs' rosters/stats from the NHL API
npm run draft      # refresh all 32 clubs' draft classes from the NHL API
npm run check:editorial  # structural check on every club module

Cap data comes from PuckPedia, which blocks automated crawlers, so it is read
in a human-directed browser visit and piped through
`scripts/parse-puckpedia.mjs` into `scripts/add-cap.mjs`. The parser reconciles
every group to the club's stated cap hit and refuses to stay quiet when they
disagree — that check caught a missing buyout class, two players dropped by a
name regex, a lossy abbreviated page layout and a $4M hole. Read its header
comment before the next refresh.
npm run qa         # content QA sweep: coverage, wrong-club rows, dead lookups
npm run coaches    # head coaches from Hockey-Reference (rate-limited; see below)
npm run photos     # fetch freely-licensed Wikimedia photos
npm run deploy     # deploy the default site (see docs/INFRASTRUCTURE.md)
```

`/update-data` is the skill that checks sources and updates content. It has
standing authorisation to commit and push — but only for update passes, not for
feature or design work.

## Gotchas that have already bitten

- **`scripts/_config.sh` precedence.** `.env.deploy` supplies defaults;
  exported variables win. It did not always work that way, and a deploy aimed
  at one bucket silently went to another. Every deploy prints its target first
  — read that line.
- **DNS for `metacto.com` is in Google Cloud DNS, not Route 53**, despite the
  AWS account holding hosted zones for some delegated subdomains.
- **CloudFront certificates must live in `us-east-1`.** The existing
  `*.metacto.com` wildcard already covers new subdomains.
- **The NHL API rate-limits a full-league sweep** (429s from about the twelfth
  club). Requests are serialised and paced; do not "optimise" that into
  `Promise.all`.
- **PuckPedia disallows `ClaudeBot` and `anthropic-ai`** in robots.txt. Cap data
  is read by a human-directed browser visit, never an automated scraper.
- **A league file entry does not mean the player played here.** It is the current
  roster with club stats attached where they exist, so an entry with no `gp`
  is an arrival or a prospect. A backfill once read "in the league file and on
  the roster feed" as "retained" and wrote 50 rows saying so — including players
  the same module's summary called arrivals. Require `stats.gp > 0` before
  asserting anything about a player's last season.
- **Hockey-Reference rate-limits hard.** Roughly thirty requests in quick
  succession returns `429` with a ~3500s `Retry-After`, and the block is
  site-wide rather than per-page. `npm run coaches` paces itself, aborts on a
  429 rather than hammering, and resumes with `--only-missing`.
- **The NHL API has no coaching endpoint** (`v1/coaches` 404s) and NHL.com's club
  sites are bespoke — only Calgary exposes a parseable `/team/coaching-staff`.
  Coaching comes from Hockey-Reference, and only the head coach; assistants and
  GMs are not on those pages.
- **CI verify globs `index-*.js`, not `*.js`.** The bare glob returns an
  alphabetically-early code-split chunk, which never matches the entry bundle
  scraped from the live HTML, so the step failed on every push while the S3 sync
  underneath it succeeded.
- **The OIDC trust policy constrains the environment name**, not just the repo.
  It allows `:environment:production` and `:ref:refs/heads/main`; a job declaring
  any other environment fails at `sts:AssumeRoleWithWebIdentity`, which reads
  like a bucket permissions problem and is not.
- **Pushing is deploying**, and a push is not shipped until the CI verify step
  confirms the live bundle matches the build.
