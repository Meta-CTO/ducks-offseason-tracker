# Working in this repo

An NHL offseason tracker. All 32 clubs are selectable; Anaheim carries the full
editorial treatment. Static React + Vite, built to S3 and served by CloudFront.

**This repository is public.** Never commit AWS account numbers, bucket names,
distribution IDs or ARNs. They belong in `.env.deploy` (gitignored) and GitHub
Actions variables. `docs/INFRASTRUCTURE.md` describes the shape without them.

## The rule everything else serves

Facts need primary sources; anything else must be labelled as what it is.

- A **fact** traces to NHL.com, the NHL API, PuckPedia or Hockey-Reference.
- Anything not yet official — a projected lineup, an expected role — must read
  as a projection.
- A **rumour** is not a fact and never edits the roster, cap or contract data.
  It goes in the `rumors` array with a provenance chip. See `CONTRIBUTING.md`.
- Do not generate editorial content from statistics. A club without a written
  research brief gets the data-only page, which says so plainly. That is the
  correct outcome, not a gap to paper over.

No NHL, NHLI or club logos, wordmarks, crests or league photography — anywhere,
including data files. Club identity is colour and the three-letter code. Player
photos come only from Wikimedia Commons under a free licence; everyone else
gets an initials avatar. Naming a team in text is nominative use and is fine.

## Where things live

| Path | What it is |
|---|---|
| `src/data/ducks.js` | Anaheim's editorial content: roster notes, ledger, camp watch, unresolved, rumors. Most content edits. |
| `src/data/cap.js`, `contracts.json`, `points.json` | Anaheim cap, contract terms, point totals. |
| `src/data/teams.json` | The 32-club registry. Generated by `npm run league`. |
| `src/data/league/<ABBR>.json` | Per-club roster and stats. Generated; code-split so one club costs ~6KB. |
| `src/data/updates.json` | Drives the self-expiring NEW badge. Written by the update pass. |
| `src/lib/team.js` | Team selection: URL → cookie → per-host default. |
| `docs/INFRASTRUCTURE.md` | Hosting, DNS, deploy, IAM, runbooks. |

## Two depths of club page

`EDITORIAL_TEAMS` in `src/lib/team.js` decides. A club in that set renders the
full tracker; every other club renders roster and scoring from the NHL API with
a notice explaining the narrative is missing. Promoting a club means writing its
sourced brief first, then adding it to that set.

## Commands

```sh
npm run dev        # local
npm run build      # production build
npm run lint       # oxlint
npm run league     # refresh all 32 clubs from the NHL API
npm run photos     # fetch freely-licensed Wikimedia photos
npm run deploy     # deploy the default site (see docs/INFRASTRUCTURE.md)
```

`/update-data` is the skill that checks sources and updates content. It has
standing authorisation to commit and push — but only for update passes, not for
feature or design work.

## Gotchas that have already bitten

- **`scripts/_config.sh` precedence.** `.env.deploy` supplies defaults;
  exported variables win. It did not always work that way, and a deploy aimed
  at one bucket silently went to another. Every deploy prints its target first
  — read that line.
- **DNS for `metacto.com` is in Google Cloud DNS, not Route 53**, despite the
  AWS account holding hosted zones for some delegated subdomains.
- **CloudFront certificates must live in `us-east-1`.** The existing
  `*.metacto.com` wildcard already covers new subdomains.
- **The NHL API rate-limits a full-league sweep** (429s from about the twelfth
  club). Requests are serialised and paced; do not "optimise" that into
  `Promise.all`.
- **PuckPedia disallows `ClaudeBot` and `anthropic-ai`** in robots.txt. Cap data
  is read by a human-directed browser visit, never an automated scraper.
- **Pushing is deploying**, and a push is not shipped until the CI verify step
  confirms the live bundle matches the build.
